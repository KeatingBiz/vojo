# STT and speech-analytics API comparison

Pages below were fetched on 8 November 2026 unless a source date is stated. Prices are public list or pay-as-you-go rates for US English clips under 3 minutes. Vojo’s code constants ($0.0077/min Deepgram, $0.0025/min AssemblyAI) are treated as given and compared with those pages. They were not re-read from the repo.

## November 2026 list prices, what the cheap tier drops, and streaming versus batch

### Takeaway
For a finished ~60 second file, the relevant rates are pre-recorded, not streaming. Deepgram Nova-3 monolingual pre-recorded is $0.0043/min; the $0.0077/min figure in Vojo’s constants matches Nova-3 streaming, not batch. AssemblyAI Universal-2 remains $0.15/hr ($0.0025/min). Universal-3.5 Pro exists at $0.21/hr. Groq Whisper Turbo at $0.04/hr is the cheapest sourced API, and it is batch-only. Cheap modes usually drop fillers by default, and Google’s $0.003/min Dynamic Batch is not a few-second path.

## Which vendors preserve filler words rather than cleaning them

### Takeaway
Preserving “um” and “uh” is an explicit opt-in at Deepgram and AssemblyAI, and the default at Speechmatics. Whisper-class models, including the model Groq serves, are a poor fit: on a 2026 verbatim benchmark, Whisper Large v3’s English filler F1 is 9.4%. Discourse fillers such as “like,” “so,” and “right” are not in Deepgram’s or Speechmatics’ hesitation lists, so Haiku’s ambiguous-filler check is not replaced by these APIs.

### Cited Findings
- Deepgram `filler_words` defaults to false. When false or omitted, “uh” and “um” are stripped. When true, the model emits only these spellings, regardless of duration: uh, um, mhmm, mm-mm, uh-uh, uh-huh, nuh-uh. Documented for Nova, Nova-2, and Nova-3 general models, pre-recorded and Nova streaming. Flux English is listed in the feature header. “Like,” “so,” and “right” are not in the list. — [Deepgram filler words](https://developers.deepgram.com/docs/filler-words)
- AssemblyAI’s filler-words doc: fillers are removed by default. Set `disfluencies` to true to keep them. The same page’s table says Universal-3.5 Pro supports this for English, Spanish, German, French, Portuguese, and Italian, and Universal-2 for English only. — [AssemblyAI filler words](https://www.assemblyai.com/docs/pre-recorded-audio/include-filler-words)
- AssemblyAI’s models reference, retrieved the same day, says the opposite: the `disfluencies` parameter is not supported on Universal-3.5 Pro, is silently ignored, and prompting should be used instead (“tag filler words like um and uh”). It says the parameter is supported on Universal-2. The pricing reference points to that models page for feature support and was last updated 2026-10-27. A transcript-submit API description in search results says the field is “Supported on Universal-3.5 Pro and Universal-2.” — [AssemblyAI models reference](https://www.assemblyai.com/llms/models.md); contradicted by [AssemblyAI filler words](https://www.assemblyai.com/docs/pre-recorded-audio/include-filler-words)
- Speechmatics tags hesitation sounds with a `disfluency` tag by default and removes them only if `transcript_filtering_config.remove_disfluencies` is true. Default is false. The English tag list includes um, uh, hmm, erm, mm, uh-huh, uh-uh, and many lengthened spellings (umm, uhm, uhhm). It does not include “like,” “so,” or “right.” Each tagged token still has `start_time`, `end_time`, and `confidence`. Documented for Enhanced in the examples, and the feature page does not say Melia lacks it. — [Speechmatics formatting](https://docs.speechmatics.com/speech-to-text/formatting)
- Gemini’s transcription guide: default mode `VERBATIM` keeps fillers, repetitions, pauses, and false starts, and is required when word timestamps or diarization are enabled. Mode `SMART` removes filler words, stutters, and false starts, and cannot be combined with timestamps or diarization. The English model card says Smart dictation includes filler-word removal. The verbatim/default wording was read from the official guide’s Traditional Chinese mirror; the English model card confirms Smart removes fillers but was not the page that defined `VERBATIM` as default. — [Gemini transcription guide](https://ai.google.dev/gemini-api/docs/generate-content/transcribe?hl=zh-tw); [Gemini 3.5 Transcribe model card](https://aistudio.google.com/docs/models/gemini-3.5-transcribe)
- Nyra Verbatim Speech Benchmark README (repo created 7 April 2026; leaderboard read 8 November 2026), English set `nyralabs/disfluency_speech_english`, n=4957 except where noted. Filler F1 is F1 on `[UH]` and `[UM]`. OpenAI Whisper Large v3 filler F1 9.4%, disfluency F1 9.7%, verbatim WER 10.2%. Deepgram Nova-3 filler F1 45.7%, disfluency F1 57.3%, verbatim WER 6.3%. AssemblyAI Universal-3 Pro with Prompt 2 filler F1 90.8%, disfluency F1 67.9%, cutoff F1 27.9%, verbatim WER 4.5% (n=4957). The same model with Prompt 1 is n=249 only (filler F1 92.5%). ElevenLabs Scribe v2 filler F1 95.5%. Microsoft MAI-Transcribe-1.5 filler F1 95.8% and vocal-sound F1 0. The README does not record whether Nova-3 was called with `filler_words=true`. AssemblyAI rows are explicitly prompt conditions, which matches the prompting path in the models reference, not a confirmed `disfluencies=true` call. German n=202: Nova-3 filler F1 1.0%, AssemblyAI prompts 7.8% and 3.2%, Whisper 0%. — [Nyra Verbatim Speech Benchmark](https://github.com/nyrahealth/nyra_verbatim_speech_benchmark)
- Groq serves `whisper-large-v3` and `whisper-large-v3-turbo`. The benchmark row is the OpenAI Whisper Large v3 weights, not a Groq-endpoint capture. Groq’s own docs publish a 10.3% WER for large-v3 and 12% for turbo, without saying the test keeps fillers. — [Groq speech-to-text docs](https://console.groq.com/docs/speech-to-text)

### Inferences
- Universal-2 with `disfluencies=true`, which is what Vojo sends today, is the AssemblyAI setting that both the filler doc and the models reference agree still works. Universal-3.5 Pro is not a drop-in upgrade until the `disfluencies` contradiction is tested on a real clip.
- On the English Nyra set, a prompted Universal-3 Pro kept um/uh far more often than the published Nova-3 row (filler F1 90.8% versus 45.7%) and had a lower verbatim WER (4.5% versus 6.3%), but it was much worse at interrupted words (cutoff F1 27.9% versus 72.2%). That is not “cheaper and better on every coaching feature.” It is better on um/uh and worse on cutoffs, and only if the Nova-3 run was a fair verbatim configuration. That last point is undocumented.
- Switching to Groq or OpenAI Whisper to save money would likely erase filler counts. Whisper’s English filler F1 of 9.4% means it usually deletes the tokens Vojo is trying to count.
- No fetched STT doc treats “like / so / right” as disfluencies. Those stay ordinary words. Haiku’s confirmation step is still doing something the STT vendors do not.

### Gaps
- No Speechmatics, Soniox, Gladia, Rev Reverb, AWS, Azure, or Google Chirp row on the Nyra verbatim leaderboard.
- No vendor page fetched for AWS Transcribe, Azure, Gladia, Soniox, or Rev that states whether um/uh are kept. Absence of a doc is not proof they strip them.
- The English Gemini `VERBATIM` default was confirmed on the zh-TW guide, not on a separately fetched English HTML page.
- Nyra does not publish the Deepgram query string, so Nova-3’s 45.7% filler F1 might be the default stripping behavior rather than `filler_words=true`.

## Word-level timestamps and confidence for pauses of 300 ms or more

### Takeaway
Deepgram, Speechmatics, AssemblyAI’s sync API, Groq, and Gemini file transcription all expose per-word start and end times precise enough, on paper, to compute gaps of 300 ms. None of the fetched docs state a timestamp error bound, so “good enough for 300 ms pauses” is not a published accuracy claim. Groq’s word objects, as documented, have no confidence. Gemini warns that turning timestamps on can lower transcription accuracy.

### Cited Findings
- Deepgram utterances and the base word objects include `start` and `end` in seconds and a `confidence` from 0 to 1. Example values are floats such as 0.41915998 and 0.85827994. With `punctuate=true`, each word also has `punctuated_word`, which is the sentence-boundary signal. Utterances themselves have start, end, and confidence. These fields are part of the transcription response, not a priced add-on on the pricing page. — [Deepgram utterances](https://developers.deepgram.com/docs/utterances); [Deepgram pricing](https://deepgram.com/pricing)
- AssemblyAI sync API: `timestamps` defaults to false. When true, each word has `start` and `end` in milliseconds plus `confidence`. The doc says timings are exact or omitted, never estimated, accuracy is best for English, and timestamps add latency. A 20 ms gap is visible in their example (end 200, next start 220). — [AssemblyAI sync word timestamps](https://www.assemblyai.com/docs/sync-stt/word-timestamps)
- Speechmatics results use `start_time` and `end_time` in seconds on each word, with `confidence`, and punctuation is a separate formatting layer with a sensitivity control. A disfluency token carries the same timing fields. — [Speechmatics formatting](https://docs.speechmatics.com/speech-to-text/formatting)
- Groq: `response_format=verbose_json` and `timestamp_granularities` of `word` and/or `segment`. Word granularity returns word, start, and end only. The client docs say word timestamps add latency and segment timestamps do not. No per-word confidence is described for the word payload. — [Groq speech-to-text docs](https://console.groq.com/docs/speech-to-text); [Groq Python transcription params](https://github.com/groq/groq-python/blob/main/src/groq/types/audio/transcription_create_params.py)
- Gemini file model supports word-level start and end offsets. The guide says enabling them may reduce transcription accuracy, they are incompatible with custom vocabulary and with SMART mode, and file length is capped at 30 minutes when they are on. Live `gemini-3.5-transcribe-live` does not support word timestamps. — [Gemini transcription guide](https://ai.google.dev/gemini-api/docs/generate-content/transcribe?hl=zh-tw); [Gemini 3.5 Transcribe model card](https://aistudio.google.com/docs/models/gemini-3.5-transcribe)
- Gladia’s pricing comparison table lists word-level timestamps as included on self-serve. It does not describe confidence or timestamp units. — [Gladia pricing](https://www.gladia.io/pricing)
- Rev forced alignment is a separate product at $0.003/min, which is evidence that Rev will sell timestamps as their own pass. Whether Reverb’s default transcript already includes word times was not on the pricing extract. — [Rev.ai pricing](https://www.rev.ai/pricing)

### Inferences
- A 300 ms pause is 15 times the 20 ms gap in AssemblyAI’s example and many times the sub-millisecond float resolution in Deepgram’s example. Resolution is not the risk. Alignment error is, and no vendor published an error in milliseconds.
- For pause detection, prefer a response that always returns start and end on every word, including fillers. Speechmatics puts timing and a disfluency tag on the same token. Deepgram does this when `filler_words=true`. Gemini can do verbatim plus timestamps, with an accuracy warning. Groq can time words but, given Whisper’s filler F1, the gaps would be measured on a transcript that has already deleted most um/uh, which inflates pauses and breaks filler counts.
- Punctuation for sentence boundaries is included or default at Deepgram (smart format included; `punctuate` shown in the utterances API), Speechmatics (default punctuation), and Gladia async (“enhanced punctuation,” async only). AssemblyAI’s current Vojo flags `punctuate` and `format_text` were not re-priced as add-ons; they do not appear in the add-on rate card.

### Gaps
- No sourced measurement of word-boundary error versus forced alignment or Praat for any vendor, so a 300 ms threshold cannot be validated from docs alone.
- Pre-recorded AssemblyAI v2 word objects were not re-fetched. Only the sync timestamp contract was. Vojo’s current Universal-2 integration may already receive word times without the sync flag.
- OpenAI’s transcription parameter page for `verbose_json` on `gpt-4o-transcribe` and Whisper was not fetched. Pricing confirms the models exist. Timestamp support on the deprecated `gpt-4o-transcribe` model was not confirmed.
- Google Cloud Speech-to-Text V2 `enableWordTimeOffsets` for Chirp was not fetched. A reseller table claims word timings for Chirp 2 and not for Chirp 3; that is not Google’s doc. — [SpeechRouter Google provider](https://docs.speechrouter.ai/providers/google/)

## Prosody, sentiment, and tone versus local Praat

### Takeaway
The transcription products that advertise sentiment are scoring the transcript, not pitch, uptalk, or energy. They do not replace Praat. Hume’s Expression Measurement API is the product that scores vocal expression from audio, including a documented “monotone” voice attribute, but the official pricing page fetched on 8 November 2026 no longer lists a per-minute rate. Secondary sources from earlier in 2026 say about $0.064 per minute of audio, which would dwarf STT cost. Azure lists pronunciation-assessment prosody as a real-time add-on, with no confirmed dollar price.

### Cited Findings
- Deepgram Audio Intelligence sentiment, summarization, topic, and intent are billed per token on top of transcription: pay-as-you-go $0.0003 per 1,000 input tokens and $0.0006 per 1,000 output tokens. The FAQ says they run on small language models over the transcript. That is text sentiment, not F0 or energy. — [Deepgram pricing](https://deepgram.com/pricing)
- AssemblyAI Sentiment Analysis is +$0.02 per audio hour on pre-recorded Universal-3.5 Pro or Universal-2. At 60 seconds that is about $0.00033. It is listed with entity detection, topics, and key phrases under speech-understanding add-ons, not as an acoustic feature. — [AssemblyAI pricing reference](https://www.assemblyai.com/pricing)
- Gladia sentiment analysis is €0.02/hr on async and real-time, separate from transcription. Same pattern: a cheap text add-on. — [Gladia pricing](https://www.gladia.io/pricing)
- Rev.ai sentiment is $0.0008 per 10 words, not per minute. A 150-word minute is $0.012. The pricing page does not describe acoustic features. — [Rev.ai pricing](https://www.rev.ai/pricing)
- Hume Expression Measurement overview: audio in, and for each window of speech a set of expression scores and voice-attribute scores that pass a cutoff, out of 415 expression names and 190 voice-attribute names. The overview gives `amusement` and `monotone` as examples. Scores are probabilities from 0 to 1. Upload is `POST /v1/expression/audio/file`. Billing doc: audio is billed for its full length, including silence; a successful run has a 10 second minimum; a 60 second file bills 60 seconds. The billing page does not state a dollar rate. The public pricing URL fetched the same day is a marketing page for an “audio-native decision model” and does not list Expression Measurement per-minute prices. — [Hume Expression Measurement overview](https://dev.hume.ai/expression-measurement/docs/overview.mdx); [Hume Expression Measurement billing](https://dev.hume.ai/expression-measurement/docs/billing); [Hume pricing page](https://www.hume.ai/pricing)
- A January 2026 cost PDF and a 2026 Hume review both print Expression Measurement audio-only at $0.0639/min and video-plus-audio at $0.0828/min, images $0.00204, text $0.00024 per word. These are not the official page. — [Jeff Turner voice-AI cost PDF, January 2026](https://www.jeffturner.info/wp-content/uploads/2026/01/voice-ai-cost-breakdown.pdf); [Dupple Hume review](https://dupple.com/reviews/hume)

## Quality evidence, and why a lower WER can be worse for coaching

### Takeaway
Published general WER is the wrong scoreboard for this product. A transcript that deletes “um” looks cleaner, and often scores better, when the reference has also been cleaned. On a benchmark that scores fillers separately, Whisper Large v3’s English filler F1 is 9.4% despite a verbatim WER of 10.2% that is in the same range as Groq’s advertised 10.3% WER. The useful comparison for Vojo is filler F1 and cutoff F1, not headline WER.

### Cited Findings
- Nyra’s README states the issue directly: WER depends on underspecified references, including whether a filler counts, and many models optimize for the intended transcript while dropping the phenomena that matter for conversational speech. The benchmark therefore reports verbatim WER against what was said and intended WER against a cleaned transcript, plus filler, cutoff, repetition, and vocal-sound F1. English results cited above are the ones that apply to Vojo. — [Nyra Verbatim Speech Benchmark](https://github.com/nyrahealth/nyra_verbatim_speech_benchmark)
- Speechmatics defines WER as insertions plus deletions plus substitutions, divided by reference word count. That definition does not say whether the reference keeps fillers. A 5% WER is described as 95% accuracy under that formula. — [Speechmatics accuracy benchmarking](https://docs.speechmatics.com/speech-to-text/accuracy-benchmarking)
- Deepgram’s comparison page publishes WER of 7% for Deepgram and 11.3% for Speechmatics, plus a cost of $0.0043 versus $0.0173. It does not say the test is conversational, disfluent, or verbatim. Those WER figures should not be used to choose a filler-preserving vendor. — [Deepgram vs Speechmatics](https://deepgram.com/compare/speechmatics-vs-deepgram)
- Groq publishes its own WER of 10.3% (`whisper-large-v3`) and 12% (turbo) next to the hourly price, with no disfluency protocol. — [Groq speech-to-text docs](https://console.groq.com/docs/speech-to-text)
- A Speko page measured 1 October 2026 reports Google Chirp 3 batch WER 3.9% on FLEURS (read speech, n=1541) and streaming conversation WER 18.43% on EdAcc (range 15.2–21.8%, n=283). The same page prices Chirp 3 at $0.016/min. Read-speech WER and conversational WER differ by a wide margin on that one vendor. It is not a filler test. — [Speko Chirp 3 benchmark](https://benchmarks.speko.ai/stt/google-chirp-3/)
- PodcastFillers (arXiv 2203.15135) is a 35k-filler podcast dataset and a detection pipeline. It is not a 2026 bake-off of the APIs above. It is cited only as the reason filler detection is scored with event precision, recall, and F1 rather than WER. — [Filler Word Detection and Classification](http://arxiv.org/pdf/2203.15135v2)

### Inferences
- For Vojo, a lower general WER that was earned by deleting um/uh is a regression. The Nyra English table is the only 2026 public comparison found that separates those errors. On it, prompted AssemblyAI Universal-3 Pro beats Nova-3 on filler F1 (90.8% vs 45.7%) and loses on cutoff F1 (27.9% vs 72.2%). ElevenLabs Scribe v2 and Microsoft MAI-Transcribe-1.5 lead the commercial rows on English fillers (95.5% and 95.8%) with verbatim WER of 3.2% and 3.6%. MAI’s vocal-sound F1 is 0, so “best filler F1” is not “best verbatim transcript.”
- Groq is cheaper and faster, and the Whisper result says it is worse at the feature the product computes from the transcript. That is the central pricing-versus-quality finding.
- Nothing fetched shows an API that is both cheaper than Universal-2 and better than Nova-3 with `filler_words=true` on um/uh, timestamps, and pause gaps at once. Universal-2 is already the cheap option that documents an English disfluency flag. The open question is whether Universal-3.5 Pro’s boolean flag works, or only prompting does, and whether that prompting path keeps the word times Vojo uses for WPM and pauses.

### Gaps
- No independent disfluency eval that names Deepgram with `filler_words=true`, AssemblyAI Universal-2 with `disfluencies=true`, or Speechmatics with the default disfluency tags.
- No published timestamp-error study tied to 300 ms pause detection.
- Nyra is one lab’s dataset and cached predictions (English n=4957, German n=202). It is the right task, and it is not a multi-lab replication.
