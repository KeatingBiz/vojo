## What is the exact pipeline from uploaded audio to scorecard?

### Takeaway
A daily answer is recorded in the app (up to 60 seconds, stoppable early), uploaded to `POST /analyze`, normalized to 16 kHz mono WAV, transcribed, measured with local math, then optionally judged by one Claude call; the numeric scorecard is assembled in `finish()`.

### Cited Findings
- Daily prompts all set `speakSeconds: 60` and `thinkSeconds: 30`. The record screen runs a countdown that calls `finish` at zero, and an "I'm done" button can stop earlier. Boss mode is a separate 30-second turn and does not call the grader. — [src/data/prompts.ts](file:///Users/jacobkeating/vojo/src/data/prompts.ts); [src/app/session.tsx](file:///Users/jacobkeating/vojo/src/app/session.tsx); [src/app/boss.tsx](file:///Users/jacobkeating/vojo/src/app/boss.tsx)
- Capture preset is mono AAC, 24 kHz, 48 kbps, metering on. Comment in code: "~360 KB per minute, transparent to the grader." The client posts the file as `clip.m4a` plus the prompt text to `{API_URL}/analyze`. It does not send `user_id`. — [src/lib/use-mic.ts](file:///Users/jacobkeating/vojo/src/lib/use-mic.ts); [src/lib/api.ts](file:///Users/jacobkeating/vojo/src/lib/api.ts)
- `POST /analyze` optionally requires `X-Vojo-Key` when `VOJO_API_SECRET` is set. It writes the upload to a temp file, calls `measure()`, maps `AudioError` to HTTP 400 and `TranscriptionError` to HTTP 502, then streams two NDJSON lines when `stream` is true (the default): line 1 is `m.payload(confirmed=None)` with `stage: "measured"`; line 2 is `finish()` with `stage: "final"`. `?stream=false` returns only the final JSON. — [server/main.py](file:///Users/jacobkeating/vojo/server/main.py)
- `measure()` order: `normalize()` → transcribe unless a transcript was passed in → `first_pass()` for ambiguous fillers → `analyze_pacing()` → `analyze_prosody()` → `CostLog.transcription()`. — [server/vojo_speech/pipeline.py](file:///Users/jacobkeating/vojo/server/vojo_speech/pipeline.py)
- `normalize()` runs ffmpeg (`-ac 1 -ar 16000 -c:a pcm_s16le`). Rejects duration `< 5.0` s, duration `> 180.0` s, or mean RMS `< 0.004`. Config comment: "the app caps at 60s; 3 min is a generous ceiling." — [server/vojo_speech/audio/normalize.py](file:///Users/jacobkeating/vojo/server/vojo_speech/audio/normalize.py); [server/vojo_speech/config.py](file:///Users/jacobkeating/vojo/server/vojo_speech/config.py)

With no judgment, `confirmed=None` (pause fallback) and `fallback_feedback()` templated copy; `content` is null. `meta` always includes timings, cost, and `config.CLAUDE_MODEL`. — [server/vojo_speech/pipeline.py](file:///Users/jacobkeating/vojo/server/vojo_speech/pipeline.py)

## What signals exist, and what are the thresholds in config.py?

### Takeaway
Scored signals are a closed filler lexicon plus LLM or pause resolution, whole-clip WPM, inter-word pauses, pitch standard deviation in semitones relative to the speaker's median, uptalk slope on punctuation-delimited statements, and three unbounded LLM content scores. Energy, pitch drift, windowed WPM, speaking time, and per-word ASR confidence are computed or stored and do not enter the score.

## What does "confidence" mean, and can the LLM invent it?

### Takeaway
Confidence is a local equal average of four measured curves: filler rate, pause score, pitch-variation score, and uptalk score. The LLM schema has no confidence field, the prompt forbids guessing it, and `combine()` never reads a model-produced confidence.

### Cited Findings
- `confidence_score()` docstring: "Derived ONLY from measured signals. Shown to the user as 'Confidence'." ### Inferences
- The model can still write the word "confidence" inside a note if it disobeys the prompt. That string would be coaching copy. It would not change `scores.confidence` unless some other code path, which this audit did not find, copied it.
- Because uptalk returns 85 when fewer than three statements were classified, a clip with almost no punctuation can still show a high confidence contribution from that term.

### Gaps
- Pydantic's treatment of an extra JSON key named `confidence` was not verified by running the parser. The score does not read `Judgment` for that number either way.
- No test asserts that a model payload containing a confidence number is ignored. The guarantee is structural (schema plus `combine()`), not an end-to-end model test.

## What accuracy risks are baked into the code?

### Takeaway
Fillers exist only if the ASR emits them and they hit a small lexicon. Ambiguous words without Claude become fillers from a 250 ms pause rule. Uptalk trusts ASR punctuation. Pitch is relative to the clip's own median inside 75–500 Hz. The daily clip is a phone AAC recording resampled to 16 kHz, capped around 60 seconds by the app.

### Cited Findings
- Filler detection never looks at the waveform. `first_pass()` runs on transcript tokens only. If a sound is missing from the word list, it cannot be counted. Deepgram's docstring states `filler_words` is what lets um/uh survive, which means the pipeline depends on that provider flag (or AssemblyAI `disfluencies: true`). — [server/vojo_speech/analysis/fillers.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/fillers.py); [server/vojo_speech/transcribe/deepgram.py](file:///Users/jacobkeating/vojo/server/vojo_speech/transcribe/deepgram.py); [server/vojo_speech/transcribe/assemblyai_client.py](file:///Users/jacobkeating/vojo/server/vojo_speech/transcribe/assemblyai_client.py)
- The lexicon omits words people often call fillers. Tokens not in `SOUND_FILLERS`, `WORD_FILLERS`, `PHRASE_FILLERS`, or the like/so/right rules are ignored. Examples present as non-members in the sets: there is no `well`, `okay`, `yeah`, `huh`, or `just` (and `just` is in `LIKE_VERB_PREV`, so it blocks a following "like"). `norm()` turns `uh-huh` into `uhhuh`, which is not in `SOUND_FILLERS`. — [server/vojo_speech/config.py](file:///Users/jacobkeating/vojo/server/vojo_speech/config.py); [server/vojo_speech/analysis/fillers.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/fillers.py)
- `LIKE_VERB_PREV` is a finite list. A "like" whose previous word is outside that list and is not a sound filler is ambiguous, including cases the list author did not name. — [server/vojo_speech/config.py](file:///Users/jacobkeating/vojo/server/vojo_speech/config.py)
- Math-only ambiguous resolution: pause `>= 250` ms on either side confirms the candidate. The test "It was | like a big deal" (the helper's `|` is a 1.5 s gap) counts the like when no index list is passed, and drops it when the list is empty. Sentence-initial `so` needs a 500 ms gap or punctuation, which is a different threshold than the 250 ms fallback. — [server/vojo_speech/analysis/fillers.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/fillers.py); [server/tests/test_fillers.py](file:///Users/jacobkeating/vojo/server/tests/test_fillers.py); [server/tests/helpers.py](file:///Users/jacobkeating/vojo/server/tests/helpers.py)
- Uptalk and the `so`/`right` rules split on provider punctuation. Deepgram sets `punctuate` and `smart_format`; AssemblyAI sets `punctuate` and `format_text`. `sentences_from_words()` has no pause-based sentence boundary. A run-on with no `.?!` is one statement, so only its last 0.40 s is classified, and if that yields fewer than 3 classified statements the uptalk score is 85 regardless of the slope. A false `?` drops that sentence from the uptalk ratio. — [server/vojo_speech/analysis/prosody.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/prosody.py); [server/vojo_speech/transcribe/deepgram.py](file:///Users/jacobkeating/vojo/server/vojo_speech/transcribe/deepgram.py); [server/vojo_speech/transcribe/assemblyai_client.py](file:///Users/jacobkeating/vojo/server/vojo_speech/transcribe/assemblyai_client.py)
- Pitch is "relative to the speaker's own median pitch" (module docstring). Semitones use the clip median, so a different habitual pitch does not by itself change the variation score. The tracker will not return F0 outside 75–500 Hz. Under 4 voiced frames, variation is 0 and `monotone` is true, which scores 0 on the variation curve (`variation_score` hits 0 at 0.3 st). — [server/vojo_speech/analysis/prosody.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/prosody.py); [server/vojo_speech/analysis/score.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/score.py)
- Capture chain: phone/device mic via expo-audio, mono AAC 24 kHz at 48 kbps, then ffmpeg resample to 16 kHz mono PCM. No noise reduction, AGC undo, or mic calibration step exists in `normalize()` beyond the RMS silence reject. The eval instructions tell a person to record the three reference clips "on your phone." The code does not state a measured phone-mic error. — [src/lib/use-mic.ts](file:///Users/jacobkeating/vojo/src/lib/use-mic.ts); [server/vojo_speech/audio/normalize.py](file:///Users/jacobkeating/vojo/server/vojo_speech/audio/normalize.py); [server/README.md](file:///Users/jacobkeating/vojo/server/README.md)
- Duration: app timer is 60 s with early stop; server rejects under 5 s and over 180 s. Rates divide by wall-clock `duration_s`, not `speaking_s`, with a floor of 1 s that the 5 s minimum makes unreachable for accepted clips. WPM therefore falls when the clip contains silence. — [src/data/prompts.ts](file:///Users/jacobkeating/vojo/src/data/prompts.ts); [server/vojo_speech/config.py](file:///Users/jacobkeating/vojo/server/vojo_speech/config.py); [server/vojo_speech/analysis/pacing.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/pacing.py); [server/vojo_speech/analysis/fillers.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/fillers.py)
- TTS fixture generator comment: "no fillers survive TTS well; these only exercise the plumbing." That is an explicit warning that synthetic clips are not filler ground truth. — [server/tests/make_fixtures.py](file:///Users/jacobkeating/vojo/server/tests/make_fixtures.py)
- Long-pause penalties stack: a pause `> 3` s counts in `over_1s`, `over_2s`, and `over_3s`, and if it is the longest and `> 4` s it also applies the 20-point freeze penalty. `over_2s` and `over_3s` are not per-minute. — [server/vojo_speech/analysis/score.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/score.py); [server/vojo_speech/analysis/pacing.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/pacing.py)
- Word timestamps are trusted as returned (`start`/`end` converted to ms). Nothing smooths them. Pause and WPM errors follow timestamp errors. ASR `confidence` is stored and ignored, so a low-confidence "um" counts the same as a high-confidence one. — [server/vojo_speech/transcribe/deepgram.py](file:///Users/jacobkeating/vojo/server/vojo_speech/transcribe/deepgram.py); [server/vojo_speech/analysis/pacing.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/pacing.py)
- Content scores are whatever integers the model returns inside 0–100. No calibration, exemplar, or second grader is in the code. — [server/vojo_speech/analysis/content.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/content.py); [server/vojo_speech/analysis/score.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/score.py)

### Inferences
- The hand-count filename convention `a-fillers-<handcount>` shows the authors expected filler count to be checked by ear, because the code has no other ground truth.
- Relative-to-median pitch removes habitual-pitch differences and also hides a slow climb that stays inside the same spread. That climb is the unused drift field, visible to the model as a number and invisible to the score.

### Gaps
- No measured false-accept or false-reject rate for the lexicon, the 250 ms rule, or um/uh retention is stored in this repo.
- No comment in `normalize.py` or `prosody.py` quantifies phone-mic or 48 kbps AAC error. The risk here is the capture chain that exists, not a published error bar.
- Whether Deepgram or AssemblyAI still drop some um/uh tokens even with those flags turned on is not tested in-repo.

## What does the cost log assume per minute?

### Takeaway
The cost log multiplies clip seconds by constants in `config.py`. It is an estimate for logs, and the file itself says to verify the rates. Those constants were not checked against vendor pages on 8 November 2026.

### Cited Findings
- Config comment: "models & cost (USD). Verify against provider pricing pages; these feed the per-request cost log only." Values: `DEEPGRAM_PER_MIN = 0.0077` with comment "nova-3 pay-as-you-go"; `ASSEMBLYAI_PER_MIN = 0.0025` with comment "universal, pay-as-you-go"; `CLAUDE_IN_PER_MTOK = 0.10`; `CLAUDE_OUT_PER_MTOK = 0.50`; `CLAUDE_MODEL = "claude-haiku-5-5"`. — [server/vojo_speech/config.py](file:///Users/jacobkeating/vojo/server/vojo_speech/config.py)
- Transcription line: `usd = round(seconds / 60 * rate, 5)` for provider `deepgram` or `assemblyai`. Any other provider string logs rate 0. A 60-second clip therefore logs `0.00770` USD for Deepgram or `0.00250` USD for AssemblyAI, before the final total is rounded to 5 decimals again. The seconds used are `audio.duration_s` after normalize, not a provider invoice quantity. — [server/vojo_speech/cost.py](file:///Users/jacobkeating/vojo/server/vojo_speech/cost.py); [server/vojo_speech/pipeline.py](file:///Users/jacobkeating/vojo/server/vojo_speech/pipeline.py)
- Claude line: `in_tokens / 1e6 * 0.10 + out_tokens / 1e6 * 0.50`, step name `claude:judge`, rounded to 5 decimals. Tokens come from `res.usage` on a successful parse only. A failed attempt that throws before `cost.claude` is not logged. There is no per-minute Claude rate. — [server/vojo_speech/cost.py](file:///Users/jacobkeating/vojo/server/vojo_speech/cost.py); [server/vojo_speech/analysis/content.py](file:///Users/jacobkeating/vojo/server/vojo_speech/analysis/content.py)
- `meta.cost` is `{items, total_usd}`. The eval table prints `total_usd`. The client type only keeps `total_usd`. The Vercel one-line score log (`VOJO_SCORE`) includes timings and scores and does not include the cost object. — [server/vojo_speech/cost.py](file:///Users/jacobkeating/vojo/server/vojo_speech/cost.py); [server/eval/run.py](file:///Users/jacobkeating/vojo/server/eval/run.py); [src/lib/api.ts](file:///Users/jacobkeating/vojo/src/lib/api.ts); [server/main.py](file:///Users/jacobkeating/vojo/server/main.py)
- Cached eval transcripts skip a new ASR call when `analyze_file` is given a transcript. `measure()` only calls `cost.transcription` when it performs transcription itself. A cache hit in `eval/run.py` still calls `normalize` inside `analyze_file` → `measure`, but transcription is skipped, so that re-run does not add a transcription cost item. — [server/eval/run.py](file:///Users/jacobkeating/vojo/server/eval/run.py); [server/vojo_speech/pipeline.py](file:///Users/jacobkeating/vojo/server/vojo_speech/pipeline.py)

### Inferences
- At the constants as written, AssemblyAI is logged at about one third of Deepgram's per-minute rate (`0.0025 / 0.0077`). That is an accounting assumption in the repo, not a verified bill.
- Haiku cost scales with tokens, so a long transcript plus the measurements JSON can cost more than the ASR line even though there is no per-minute Claude constant. This audit did not compute a typical token count.

### Gaps
- Live Deepgram, AssemblyAI, and Anthropic prices on 8 November 2026 were not fetched. The config comment already treats the numbers as possibly stale.
- No sample `meta.cost` from a production request is stored in the repo, so typical USD per daily answer is not known from this audit.
